# 完整 GP：相同總時間的位置選擇比較（預定方案 v1）

本目錄獨立於既有結果。此文件保存事前登錄的設計、種子、初始表達式與來源雜湊。下列 10 個配對種子及每 run 120 秒是本次預定設計。

## 研究問題與比較

在相同端到端搜尋時間下，沿用已凍結的行為 A 排序器，是否比結構排序或隨機選位置找到更好的最終規則？上一輪固定父代／片段的確認結果中，A 相對結構排序的平均保留正改善為 +0.07627 箱／組，但 95% 區間跨零；這不構成完整 GP 有效的證據。

| 方法 ID | 歷史片段的候選位置選擇 |
| --- | --- |
| `uniform_position_gp` | 在共同試插產生的結構合法位置中等機率選一處 |
| `structure_position_gp` | 使用凍結的結構排序器選一處 |
| `behavior_A_position_gp` | 使用凍結的行為 A64 排序器選一處 |

三組均為會更新父代的完整 GP，使用相同歷史片段庫。這輪不再加入固定父代、基本 GP、隨機片段庫或新模型。B64 不參與線上搜尋，也不另開 B 方法；若需 B 的完整 GP 比較，另行登錄。沒有事後最佳位置 oracle 的搜尋組，因為那需要額外完整品質標籤。

本輪隨機位置組是「共同多位置提案機制的隨機對照」。原始歷史片段 GP 每次先選單一位置，此輪共同機制先生成最多三個位置，因此不得將新對照宣稱為與舊 GP 完全相同，或把兩批時間直接混用。

## 規模與固定 GP 主體

- 3 方法 × 10 個新配對搜尋種子 = 30 runs，種子見 `config.json`，執行順序見 `run_schedule.csv`。
- 每 run 總時間上限 120 秒；名義搜尋預算合計 3,600 秒（60 分鐘）。準備、測試、程序清理與分析另報實測成本，不把名義上限寫成實際耗時。
- 每個種子共用 Best-fit 加 15 個基本算子隨機表達式；計畫保存在 `initialization_plans.json`。不注入歷史完整好程式，不為重複或失敗初始化補抽。
- 三方法各自在自己的時間內重新產生並核對同一初始化、完整評估 16 個名額。初始化不是免費的離線適應值；不用跨方法或舊實驗的適應值快取。
- 族群上限 16；有效候選按平均箱數、展開後節點數、execution AST key 排序並去除相同 execution AST，保留前 16。父代與交叉的第二父代均由當前族群均勻抽取。
- 運算子比例沿用交叉 50%、子樹替換 35%、常數突變 15%。採連續 112 次一區塊，每完整區塊固定 56／39／17 次，依配對種子及區塊編號洗牌；最後不足一區塊自然截斷。時間制不另設 128 名額上限。
- 子樹替換中 50% 使用歷史片段、50% 使用基本算子；沿用型別 S／V／BS／BV、原始 eligible 庫 1,240 片段、完整歷史根排除、常數加 Normal(0,5)、展開後節點 ≤64、深度 ≤8。沒有因 Worst-fit 或探針不變而刪片段。
- 所有有效且結構合法的已選子代都在完整五例 `pilot_dev` 評分；包括重複程式。無效、重複、超限、無合法位置均記錄一次主提案，不免費補抽。

## 共同位置提案：只改歷史 V 片段的內部替換

每次主提案先按原 GP 抽運算子、父代、anchor 位置／型別、donor／片段。基本子樹、交叉、常數突變，以及歷史片段的純量、遮罩或根替換，全部維持原單位置操作，不使用排序器。

只有「歷史片段替換且 anchor 是非根 V 位置」啟用以下共同程序：

1. 固定同一父代與同一個 V 片段。列出父代全部非根 V 位置；保留 anchor，再從其餘位置均勻不放回抽最多兩處。採獨立固定 RNG channel，按標準 AST path 排序後抽樣，不因方法或品質結果重抽。
2. 三方法都實際建構並檢查這最多三個完整子代，支付相同結構檢查。根據原有 64 節點／8 深度限制判斷；每一處超限、重複或建構錯誤均保留日誌，禁止悄悄改抽片段或位置。
3. 零處合法：本次結束；一處合法：直接選該處；至少兩處合法：依各方法的位置規則選一處進行完整開發集評估。
4. 行為 A 只在至少兩處合法時，對全部合法試插子代執行 A 的 64 狀態探針；父代 A 指紋第一次需要時建立。同分、探針執行失敗或選箱不變都是輸入訊號，不是硬性淘汰條件。即使所有排名分數為負，也選一處。
5. 位置選擇及分數須在該提案任何新子代完整裝箱前保存；只完整評估選中的一個子代。未選位置不得為了補標籤而在線上額外評估。

排序特徵、係數、縮放、未知上層運算子映射及固定 hash 平手規則，全部與來源 `explore.py` 一致。保留 A64 分母，不以當次有效狀態數更換分母。使用完整凍結的 128 狀態檔核對來源，但線上僅讀 A64；B64 不執行、不計入 A 的必要成本。

排序器用於所有上述合格提案，不按父代品質另外調門檻。原訓練集中父代至少達 Best-fit，因此要分層記錄父代優於／等於／差於 Best-fit 的使用次數；對弱父代的泛化仍是本輪待驗證事項。兩個合法位置不足時的共同直通也必須記錄，不能只報排序器有機會作用的子樣本。

## 真實等時間規則與快取

用一個排程器依鎖定順序逐 run 執行；同時最多一個搜尋 run、一個候選評估 worker，BLAS／OMP／MKL 各一執行緒。不得讓某些方法與其他 run 同時搶 CPU。記錄 CPU、OS、Python、NumPy、有效 CPU affinity 及程序數。

每 run 由排程器在啟動新搜尋程序前以 `perf_counter` 記錄 t0，截止時間為 t0+120 秒。Python 啟動／匯入、載入資料與片段庫、初始化產生與評估、模型載入、父代指紋、試插、編譯、探針、推論、選拔、日誌與 checkpoint 的線上成本均在時間內。不得在 t0 前為某方法預熱模型、候選或父代快取。OS 檔案快取無法完全重設，使用配對區塊的平衡執行順序減少影響並記錄 run 時間。

候選執行仍限制 512 MiB；單次完整評估 timeout 為 min(120 秒, 該 run 剩餘時間)。截止時停止新工作並終止尚在執行的候選程序。只有在截止前完成全部五例且已提交族群更新的結果可算搜尋收益；部分實例、晚完成或晚提交者全部記為 truncated，不可事後補算成成功。初始化未完成則記錄不足；可輸出截止前已有的有效最佳候選，不延長時間補滿。若一支有效候選也沒有，該 run 留作搜尋失敗，不能排除或換種子。

截止後保存已存在的記憶體狀態、程序終止及檔案收尾只算行政開銷，不執行評分／探針／選拔。另記 deadline overshoot 與清理耗時，避免把 120 秒上限誤稱為零誤差的程序總耗時。超過截止才完成的子代不能成為最終候選。

僅允許每 run 自己的探針快取，以 `(execution_AST, state_pool_SHA, state_id)` 為 key，保存有效性、分數／決策與成本；父代和子代使用相同規則。快取查詢與建立都計時，run 間清空。完整裝箱品質不得快取，合法重複子代照常評估。共同離線歷史抽取與排序器訓練屬既有成本，另列來源及一次性成本，不聲稱為零；新 LLM 呼叫固定為零。

## 資料、選擇與主要判準

搜尋只讀凍結的 `pilot_dev`：五例、容量 100、每例 5,000 物品；這批原 pilot 使用 floor。不更換搜尋資料，以維持這次方法差異可解釋。`pilot_val` 與已反覆查看的 B 不選方法或最終規則。

所有 30 runs 完成或到截止後，依各自開發最佳凍結 30 個輸出 AST／程式／雜湊與選擇時間，之後才建立並讀取新測試批次。預定 30 個獨立實例，使用已核對官方 B 生成設定：PCG64、45×Weibull(shape=3)、clip[1,100]、`np.round` ties-to-even、容量 100、5,000 物品，原物品順序；種子見 `test_data_plan.json`。這是相同官方設定的新實例，不是論文原始物品清單。

生成時須對本專案既有資料建立清單並逐例比較物品序列 hash，保存 generator 版本、參數、種子與 overlap audit；新種子不代表已證明無重複。若碰巧重複，按事先列出的備用種子順序替換，僅依內容重複判斷，禁止查看規則品質再換資料。

對 30 個搜尋輸出及 Best-fit／公開 EoH／歷史最佳三個固定參考評估同一新批次，最多 33×30＝990 次完整實例評估。可對完全相同的最終程式重用測試結果，但保留全部 run 的列與 nominal／physical 計數。參考不是新搜尋成果。測試執行失敗保留，主分析不得只報成功個案；同時報完整有效率。若有任一主要配對輸出無法完成測試，不以有效子樣本宣稱主要比較勝出。

**主要終點**：每個配對搜尋種子先對 30 例取平均，計算「結構排序箱數 − 行為 A 箱數」，再對全部 10 種子等權平均。正值代表 A 較好。報每種子結果、平均／標準差、中位數、勝平負及配對種子 bootstrap 10,000 次的 95% 區間（固定種子見 config）。區間是探索性估計；10 個種子的解析度有限，不把 300 個 seed×instance 配對當獨立樣本。

次要比較為 A 對隨機位置、結構對隨機位置；另報交叉重抽種子與實例的區間、開發集相對初始化改善、時間 30／60／90／120 秒的最佳品質曲線、第一次改善時間與首次達最終品質時間。不以主要結果不佳改換成命中率或只分析成功種子。僅在主要差異為正且其區間支持、A 對隨機也有一致收益並無有效率／成本問題時，才稱本輪有支持證據；其餘如實報方向與不確定性。

等時間下若 A 因額外檢查而完成較少評估，這就是方法成本，不能補額外時間。報全 run 的主提案數、全部試插數、超限與建構錯誤、完整評估啟動／完成／失敗／截斷數、重複率、父代繁殖次數、真正參與排序比例、排序改變位置的比例、父代品質分層、快取命中、各成本段及 wall-clock。不能用固定試插確認中的反事實耗時估計宣稱 GP 實測加速。

## 停止條件與實作邊界

本預定輪固定 30 runs，不按勝負追加種子、延長時間、換模型、調門檻或補抽正例。硬體／檔案損壞等基礎設施故障可在未查看該 run 品質的情況下，保存失敗痕跡並重啟整個同種子三方法區塊一次；候選無效或效果差不是重跑理由。不能續接 checkpoint 取得額外有效搜尋時間。

本目錄提供**方法與資源預登錄**，不是已完成的執行器。正式啟動前須在另一份 execution lock 中保存新 GP 執行器的 hash、deadline／程序終止稽核、三方法共同提案與不同選位的靜態重播檢查及環境快照；只能用手寫小樹／合成狀態做實作檢查，不以新研究種子的品質調整方法。若必須變更本方案，須另立修訂並記錄原因，不覆寫本次 lock。當前不進行 GP 搜尋、不生成測試標籤、不修改既有封存結果、不上傳 GitHub。

`prepare_registration.py` 只建立計畫／複製凍結輸入；`audit_registration.py` 只驗證檔案、配對、種子與預算，不執行裝箱或訓練。
