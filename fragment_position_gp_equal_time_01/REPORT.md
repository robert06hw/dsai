## 解讀與成本

主要分析單位為配對搜尋種子，30 個實例先在每個種子內平均；不把 300 筆 seed×instance 視為獨立重複。`comparisons.json` 同時提供種子與實例的交叉 bootstrap 敏感性結果。10 種子為有界探索，不依結果追加或調整模型。

線上初始化、載入、試插、探針、排序、完整評估及日誌均在 120 秒截止內。`run_cost_and_mechanism.csv` 保存逐 run 的成本、失敗、重複、可排序機會、父代品質分層與快取使用；committed 計數不含截止中止的最後工作，physical 欄位另保留其啟動及部分結果。終止與收尾的 overshoot 另報，晚完成結果不進入族群。


搜尋仍使用已看過且 floor 取整的 pilot_dev；新測試使用官方 round 取整設定。狀態與排序器是先前開發材料，保持凍結，沒有利用新測試回訓。

原始輸出與時間證據：`outputs_freeze.json`、`runs/*/commits`、`runs/*/proposals`、`runs/*/fitness`、`execution_lock.json`。新資料與逐例品質：`test_data_manifest.csv`、`test_nonoverlap_audit.json`、`test_instance_results.csv`。所有種子與陰性結果均保留。

## 執行修訂與完整性

前兩次啟動分別遭遇 Windows 診斷編碼及 OneDrive 暫時鎖檔，已封存；未依其品質決定重啟。額外重啟取得使用者明確核准，見 `restart_authorization_02.json`，不宣稱完全未偏離原一次重啟上限。修訂只處理診斷解碼與檔案寫入，所有重試都計入時間，方法、模型、種子及120秒上限不變。失敗啟動的可量測成本另列 `cost_accounting.json`，沒有事後將失敗寫成有效候選。

逐 run 的初始化、截止提交、選位先於完整品質、凍結排序分數及新資料去重已稽核。
